## Brechas que bloquean convertir esta lista en API web

1. **Mismo nombre no implica misma capacidad.** api.py:210–227 delega a las rutas maduras de Unreal. servidor.py:83–138 arma spec sin biblioteca de funciones y compila/ejecuta directamente graph; no hace `_expandir_funciones` ni el despacho Flow de api.py:367–489. Compartir esa orquestación pura antes de declarar equivalencia para funciones y Flow.
2. **El canvas de los agentes sigue siendo Slate.** api.py:88–161 guarda lo publicado y encola aplicaciones de texto. El web sólo lee grafo_inicial al arrancar (editor.js:411); no publica ni sondea el buzón. Exponer/compartir canvas_publicar y canvas_pendiente con revisión de documento; conservar leer_canvas/aplicar_texto/ayuda_texto/run_text para clientes externos en ambas puertas.
3. **No alcanza con sumar nombres a frozenset.** Ambos transportes convierten cada argumento a str (web.py:110; servidor.py:198). inspect_json aplica bool(descendente) (api.py:526), de modo que "false" y "False" son True. ghost_target recibió floats/bool reales desde C++ (JamEditorModule.cpp:1380). Cada handler nuevo necesita decodificación explícita de tipos y un resultado JSON uniforme.
4. **Hay resultados que son texto, no JSON.** confirm/discard/run/commit/preset_save_* tienen caminos de texto. editor.js:28 intenta JSON.parse de toda cadena resultado: agregar endpoints crudos rompe al consumidor. Envolver respuestas textuales, respetar report/ok/nodes y no deducir el éxito sólo de un ok ausente. preview actual incluso devuelve ok=True en api.py:263 sin analizar el texto retornado.
5. **Archivos e imágenes necesitan transporte web.** tool_import y function_manage(export) reciben rutas del host elegidas por diálogo nativo; el navegador necesita carga/descarga por contenido. preview_2d devuelve ruta en Saved/JamPreview2D (api.py:842–889), que el navegador no puede resolver como URL.
